{% comment %} Keyboard navigation for report/list tables (no mouse needed). Included ONCE by base.html, so it is available on every page and every table in the project; nothing needs to be added per page. Enter switches table navigation on: the first row is highlighted in blue. Enter again switches it off and removes the highlight. ArrowDown next row. ArrowUp previous row. Both stop at the first and last row, and the page scrolls just enough to keep the selected row in view. Which rows: by default every body row of every table inside
(`main table > tbody > tr`), in page order, as one continuous list -- on a page with two tables (e.g. بنزین معمولی / سوپر) the arrows simply carry on from the first table into the second. A table opts out with data-row-nav="off". Placeholder rows (a single cell spanning the table, such as "no data") are skipped. Rows tied together by a rowspan (e.g. the petroleum ledger's day with several purchase invoices) move and highlight as ONE row, so the highlight never covers only half of a day. A page that needs more configures it with TableRowNavigation.init({...}): rowsSelector which rows to navigate (default as above) hintId an element on the page shown while navigating (a small fixed hint is created if none is given) onArrowOutsideTableMode function(event) called for ArrowUp/ArrowDown when table navigation is OFF (the nozzle ledger uses it to change nozzles); with none, the arrows keep their normal browser behaviour. Enter does nothing except toggle the mode, and only when there is a row to navigate. Every key is ignored while the user is typing in or operating a control (input, select, textarea, button, link, editable element) and when Ctrl/Alt/Meta is held, so it never collides with the Enter-to-next-field script (partials/_enter_next_field.html), form fields, the "+" shortcut on the purchases list, or any browser shortcut. {% endcomment %}
